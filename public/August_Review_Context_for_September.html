1. Project Overview

  • Project: Population Health — Diabetes (T2DM Unplanned Admission Risk Prediction)
  • Cohort: 300,290 T2DM patients, 7.47% base rate (unplanned admission in next 12 months)
  • Model: H2O Driverless AI, classification on binary TARGET (TOTAL_UNPLANNED > 0)
  • Feature architecture: 11 clinical dimensions + CGM + Insulin Pump + Care Gap Indicators
  • Schema: bsmh_ds_ph_wip for all project tables
  • Current benchmark: PR-AUC 0.427 (H19, August 2026) — up from 0.396 (H17, July 2026)

2. August Experiments — Final Status

Experiment A: Monitoring and Care Gap Indicators — PASS, NEW BENCHMARK

  • Result: PR-AUC 0.427 (+0.031, +7.9%) — largest single-experiment gain in project history
  • Features: 12 binary indicators (11 care-gap flags + 1 aggregate count) from tbl_missingness_features_target
  • Key finding: no_nutrition_22mo ranked #1 in model importance (entire model). no_diabetes_education_22mo top 10.
  • FE notebook: ID 4340248994364321
  • CRITICAL NUANCE (extensively analyzed and documented in August review):
    • The univariate relationship is COUNTERINTUITIVE: patients WITH gaps have LOWER admission rates (e.g., 5.5% vs 32.6% for nutrition counseling)
    • This is confounding by indication — sicker patients receive more monitoring
    • Even within severity strata, the confounding persists (tested across quartiles of N_DISTINCT_CLINICAL_GROUPS)
    • Within nutrition counseling recipients: admitted vs non-admitted have virtually identical gap burden (3.8 vs 3.9/11) — what separates them is prior severity (2x prior IP, 2x ED, +47% charges)
    • The +0.031 proves the features carry non-redundant information, but the mechanism is multivariate interaction, not a simple “gaps = higher risk” rule
    • DO NOT claim that offering missing services (e.g., nutrition counseling) to flagged patients would reduce admission risk — the data does not support this causal interpretation
    • The model’s value is PRIORITIZATION (who needs attention), not PRESCRIPTION (what to do)
  • PROC_ID validation: IDs sourced from Epic procedure dictionaries; formal Clarity team validation is still pending (Andrew Parker). Do not claim validated.

Experiment B: Care Utilization Patterns — PASS, FEATURE RETAINED

  • Result: PR-AUC 0.3971 (+0.0009) — marginal aggregate gain, but one feature ranked #2
  • Features: 14 care-pattern features from tbl_care_patterns_features_target (300,290 rows)
    • 6 encounter-pattern (visit spacing, CV, regularity, distinct specialties, fragmentation ratio, distinct providers)
    • 6 scheduling-behavior (no-show count/rate, cancellation count/rate, LWBS count, appointment lead time)
    • 2 ED revisit (72-hour bounce-back, 30-day revisit)
  • Key finding: n_distinct_specialties ranked #2 out of 299 features — strongest newly-added feature ever
  • Decision: n_distinct_specialties permanently retained in production feature set. Other 13 overlap with existing features.
  • Data sources: cp__pat_enc, cp__f_sched_appt, cp__pat_enc_hsp, cp__clarity_dep
  • Specialty fragmentation IS legitimately actionable — care coordination can reduce it (different from the care-gap causal claim)

Experiment C: Baseline Feature Recovery — NEGATIVE RESULT, CLOSED

  • Result: PR-AUC 0.395 (vs 0.396 benchmark) — no improvement
  • What was tested: 349 surviving legacy features (from old 854-feature model) combined with current 285
  • Conclusion: Legacy features are different column names for the same concepts. Current 11-dimension architecture is complete.
  • Line of investigation: permanently closed.

7. Lessons Learned / Design Decisions from August

Document integrity

  • Do not claim causal relationships without evidence. The care-gap “actionable” claim was caught and corrected across all 3 documents. The model predicts; clinicians decide interventions.
  • Do not claim validation that hasn’t happened. The PROC_ID validation language was softened after the user flagged it.
  • Write documents as completed work, not planning artifacts. The Experiment B section was originally written in stages (feasibility → planning → results) and had to be consolidated into a single coherent narrative.

SWD (Storytelling with Data) principles for clinical summary

  • One message per slide
  • Hero numbers as visual anchors (5.9x, +0.031, #2)
  • Plain language for clinical audience (“Of 100 flagged, how many admitted?” not “PPV”)
  • Blockquote takeaway at the end of each slide
  • Styled HTML divs for callouts (green for improvements, blue for metrics)
  • Slide counter badges (SLIDE X OF Y)
  • Keep slides focused — split dense slides rather than overloading

Technical notes

  • python-pptx needs %pip install + %restart_python on Serverless (not pre-installed)
  • Canonical train/test split: H10 PAT_ID-membership split — never use sklearn.train_test_split for H2O exports
  • Unicode in notebook markdown: U+2019 apostrophes, U+2014 em dashes — must match exactly in editAsset patches

Critical note on model selection: The H19 benchmark (PR-AUC 0.427) is an H2O Driverless AI model, not the XGBoost models logged in MLflow. The current prediction pipeline’s model-loading logic (Section 4) uses mlflow.xgboost.load_model() and selects from the T2DM_Unplanned_Admission_XGBoost experiment. If we want to score with H19 (H2O), we need a different scoring path — either: - (a) Export H2O’s MOJO/pipeline and score via h2o or datatable runtime, OR - (b) Retrain an XGBoost model on the full H19 feature set and log it to MLflow, OR - (c) Accept the best available XGBoost model as the scoring model (lower PR-AUC than H19)

Decision needed before execution. This plan assumes option (b) or (c) for now — the pipeline structure remains the same either way.

Key Risks and Decisions

  1. H2O vs XGBoost scoring model — The H19 benchmark is H2O DAI. The pipeline currently loads XGBoost from MLflow. Either retrain XGBoost on the full feature set or integrate H2O MOJO scoring. This is the gating decision.

  2. Insulin pump codes unvalidated — The 310-ID INSULIN_PUMP_USER candidate list has NOT been SME-reviewed by Andrew Parker. Including it in predictions carries the same risk as training — the codes may be imprecise. Consider flagging pump-based predictions with a confidence caveat.

  3. PROC_ID validation pending — Care gap indicators use PROC_IDs that haven’t been formally validated by the Clarity team. Same caveat applies.

  4. Cohort size may shift — The July 2026 anchor date means a different 22-month window (Sept 2024 – July 2026). Patient counts may differ from the training cohort (300,290, anchored March 2024). This is expected.

  5. Risk tier thresholds — The current thresholds (High ≥ 0.15, Low < 0.05) were set for earlier XGBoost models. H19’s probability distribution may require recalibration. Run a distribution check before committing.
